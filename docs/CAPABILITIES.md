# Capability Matrix — FunPay Automation OS

Что реально автоматизировано, что выполняется вручную, что не поддерживается
намеренно (запрещено ТЗ и правилами площадок). Обновлено 2026-10.

## Интеграции

| Действие | Площадка | Режим | Механизм |
|---|---|---|---|
| Получение заказов/сообщений/лотов | FunPay | MANUAL (по умолчанию) | Официального публичного API нет; оператор вносит данные, приложение ведёт учёт |
| Чтение своих заказов (поллинг) | FunPay | НЕОФИЦИАЛЬНО (по явному согласию) | `golden_key` → страница «Мои продажи»; клиент `golden_key_client.py`, написан с нуля, лимиты уважаются |
| Чтение входящих сообщений чатов | FunPay | НЕОФИЦИАЛЬНО (по явному согласию) | `golden_key` → список диалогов (`chat_bookmarks`) + история чата; до 10 непрочитанных чатов и 5 последних входящих за опрос |
| Автоответы на команды | FunPay | AUTO_SAFE только | Пары «команда = ответ» из настроек (префикс, без регистра); вне АВТО-режима/в DRY RUN — черновик оператору |
| Публикация лотов (по продуктам ОС) | FunPay | НЕОФИЦИАЛЬНО (по явному согласию) | `golden_key` → форма `lots/offerEdit` + `lots/offerSave`; подтверждение оператора, лимиты уважаются |
| Закрытие/открытие лотов | FunPay | НЕОФИЦИАЛЬНО (по явному согласию) | Деактивация через `offerSave` (`active` выключается, лот НЕ удаляется); повторное открытие обратимо |
| Синхронизация цены лота | FunPay | НЕОФИЦИАЛЬНО (по явному согласию) | Цена продукта → `offerSave` с допуском расхождения (%); цена ниже минимальной не публикуется (предупреждение) |
| Публикация/обновление лотов (прочее) | FunPay | MANUAL | Тексты генерируются приложением, публикуются оператором вручную |
| Отправка сообщений | FunPay | MANUAL approval | Черновик → подтверждение → отметка об отправке |
| Авто-выдача цифрового товара покупателю | внутренний склад | AUTO/ASSISTED | Workflow Engine + StockUnit; сообщение в чат заказа — только в неофициальном режиме и с учётом DRY RUN/безопасного режима |
| Цены конкурентов | FunPay | MANUAL | Скрейпинг не используется (не обходим защиты); снапшоты вводятся оператором |
| Библиотеки аккаунтов | Steam | AUTO | Официальный Steam Web API (ключ в keyring) |
| Метаданные игр (цены/жанры) | Steam | AUTO | публичный store endpoint, rate-limited |
| Eligibility Steam Families | Steam | AUTO + MANUAL override | Официального признака нет: датасет + правила + ручные проверки |
| Состав семьи (добавить/удалить) | Steam | MANUAL | Только вручную в клиенте; приложение считает кулдауны |
| Поиск стримов игры | Twitch | AUTO | Официальный Helix `GET /streams`, `GET /games` (app token) |
| Список кампаний / прогресс / клэйм дропов | Twitch | MANUAL | Официальных публичных эндпоинтов НЕТ; только ручные действия пользователя |
| Открытие стрима/инвентаря | браузер | полу-авто | Запуск браузерного профиля ОС (пользователь уже авторизован сам) |

## Запрещено (не реализуется никогда)

Фальсификация просмотра/активности, обход CAPTCHA/2FA/антибота, кража и
перенос сессий, массовое создание аккаунтов, прокси-ротация для обхода
лимитов, подделка дропов. Любой этап, который нельзя корректно
автоматизировать, становится `MANUAL ACTION REQUIRED`.

## Режимы безопасности приложения

| Режим | Поведение |
|---|---|
| `DRY RUN` | только чтение/превью; никаких выдач, сообщений, внешних изменений |
| `AUTOMATION=OFF` | workflows не запускаются автоматически |
| `AUTOMATION=ASSISTED` (по умолчанию) | каждый внешний шаг требует approve |
| `AUTOMATION=AUTO_SAFE` | заранее разрешённые безопасные действия выполняются сами |

## Неофициальный режим FunPay (golden_key)

* **Только по явному согласию** оператора (`Настройки → FunPay → неофициальный
  доступ`), по умолчанию выключен. Официального публичного API у FunPay нет.
* Клиент `app/integrations/funpay/golden_key_client.py` **написан с нуля** для
  этого проекта (чистая реализация). Код сторонних проектов (в т.ч. референсного
  бота автоматизации, у которого **нет лицензии**) НЕ копировался — использованы
  только наблюдаемые факты протокола (см. `docs/RESEARCH.md` §6).
* Секрет `golden_key` хранится только в системном хранилище (keyring); в БД и
  конфиге — ссылка `keyring://funpay/golden_key`.
* Лимиты частоты (429 / «подождите») **уважаются**: клиент ждёт указанное время
  и повторяет, а не обходит защиту. При 403/разлогине честно сообщает об ошибке.
* Возможности: чтение своих заказов (страница «Мои продажи»), чтение
  непрочитанных чатов и их истории (входящие сообщения, дедуп по внешнему
  ID), отправка сообщения в чат заказа (автовыдача) и настраиваемые
  автоответы («команда = ответ»; автоотправка только в АВТО-режиме без
  DRY RUN, иначе черновик), автосоздание, закрытие и синхронизация цен
  лотов по продуктам ОС (создание через форму `offerEdit`/`offerSave`,
  закрытие = деактивация без удаления, цена обновляется с настраиваемым
  допуском и защитой минимальной ценой; только после подтверждения оператора
  либо автосинхронизация в АВТО-режиме без DRY RUN).
* Риски: внутренний веб-протокол может меняться; автоматизация аккаунта
  формально может нарушать правила площадки → риск ограничений аккаунта
  несёт оператор.

## Атомарность

* `stock_units`: резервирование одним `UPDATE ... WHERE status='READY'`
  с проверкой количества изменённых строк (двойной заказ не получит один юнит).
* `game_licenses` / `access_leases`: частичный уникальный индекс на активные
  аренды по лицензии.
* `twitch_accounts`: переходы статуса только через условный UPDATE.
