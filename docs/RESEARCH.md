# Исследование: Steam / Steam Families / FunPay — что можно автоматизировать

Дата исследования: 2026-10-05. Все выводы зафиксированы до начала реализации и
влияют на архитектуру (см. `docs/ARCHITECTURE.md`).

---

## 1. Steam Families — актуальные ограничения (2026)

| Правило | Значение | Источник |
|---|---|---|
| Размер семьи | до **6 участников** (включая организатора) | [1](https://dtf.ru/marketdtf/5195530-steam-families), [3](https://iwillplay.ru/blog/guides/semejnyj-dostup-v-stim-kak-sozdat-semejnuyu-gruppu-v-2026-godu) |
| Число семей на аккаунт | ровно **1**; одна семья одновременно | [5](https://steampass.gg/blog/19) |
| Регион | все участники должны быть из **одного региона** Steam | [1](https://dtf.ru/marketdtf/5195530-steam-families) |
| Возраст аккаунта | не менее 30 дней с регистрации | [2](https://tenchat.ru/media/5178401-kak-sozdat-semyu-v-stim-v-2026-instruktsiya-nastroyki-ogranicheniya) |
| Кулдаун вступления | вступить в новую семью можно через **1 год после ВСТУПЛЕНИЯ в предыдущую** (не после выхода) | [1](https://dtf.ru/marketdtf/5195530-steam-families) |
| Заморозка слота | слот, освобождённый вышедшим участником, **закрыт для новых людей на 1 год** с момента выхода; сам вышедший может вернуться без ожидания | [1](https://dtf.ru/marketdtf/5195530-steam-families), [3](https://iwillplay.ru/blog/guides/semejnyj-dostup-v-stim-kak-sozdat-semejnuyu-gruppu-v-2026-godu) |
| Одновременная игра | **1 копия игры = 1 одновременный игрок**; N копий = N одновременных игроков | [3](https://iwillplay.ru/blog/guides/semejnyj-dostup-v-stim-kak-sozdat-semejnuyu-gruppu-v-2026-godu), [5](https://steampass.gg/blog/19) |
| Исключённые игры | игры, требующие сторонний лаунчер (EA App, Ubisoft Connect и т.п.), сторонний аккаунт, отдельный ключ или подписку, **не шарятся** (решение издателя) | [1](https://dtf.ru/marketdtf/5195530-steam-families), [3](https://iwillplay.ru/blog/guides/semejnyj-dostup-v-stim-kak-sozdat-semejnuyu-gruppu-v-2026-godu) |
| Бесплатные игры | F2P-игры **не делятся** через семью (каждый играет на своём бесплатном доступе) | [1](https://dtf.ru/marketdtf/5195530-steam-families) |
| Скрытие игр | владелец может вручную скрыть отдельные игры от семьи | [2](https://tenchat.ru/media/5178401-kak-sozdat-semyu-v-stim-v-2026-instruktsiya-nastroyki-ogranicheniya) |
| VAC-ответственность | VAC-бан за читы в общей игре может затронуть и владельца копии | [4](https://kod.ru/kak-sozdat-semyu-v-stim) |

### Следствия для приложения

* Семейные слоты — **дефицитный ресурс с годовыми кулдаунами**. Приложение не
  должно проектироваться в предположении «добавил/удалил участника в любой
  момент». Управление составом семьи = отдельная, ограниченная, только ручная
  операция с отображением реальных кулдаунов (экран «Steam» → карточка семьи).
* Количество продаваемых одновременных доступов к игре = количество копий игры
  на аккаунтах семьи → сущность `GameLicense` (одна запись на копию).
* Приложение **никогда** не выполняет программных операций над составом семьи и
  не обходит ограничения; только учёт и напоминания.

## 2. Официальные интерфейсы Steam

| Интерфейс | Статус | Как используем |
|---|---|---|
| **Steam Web API** (`IPlayerService/GetOwnedGames`) | Официальный, нужен бесплатный API-ключ (https://steamcommunity.com/dev/apikey). Поддерживает `include_appinfo`, `include_played_free_games`, `include_extended_appinfo`, `include_family_licenses` (общие игры помечаются флагом `family_shared`) | Основной источник библиотек аккаунтов. Требует публичный профиль аккаунта либо ключ владельца. [документация](https://steamwebapi.azurewebsites.net/) |
| **Steam Web API** (`ISteamUser/GetPlayerSummaries`) | Официальный | Имя, аватар, статус аккаунта. [1](https://steamdb.info/faq/) |
| **Store metadata** (`store.steampowered.com/api/appdetails?appids=...`) | Публичный недокументированный endpoint магазина (не «официальный API», но открыт для чтения) | Цена, жанры, дата релиза, тип. Используется с жёстким rate-limit (≈1 запрос/сек, паузы, кэш) и деградацией при 429/503. |
| **Eligibility Steam Families** (поддерживает ли игра семью) | **Официального публичного НЕТ.** Сторонний ориентир — список исключений `exfgls` на SteamDB | Реализовано как `FamilyEligibilityService`: эвристики (сторонний лаунчер/аккаунт/подписка), локальный датасет исключений, ручные переопределения, кэш результатов с источником и датой проверки. |

Запрещено и **не реализовано**: обход CAPTCHA/Steam Guard/2FA, кража сессий,
использование чужих закрытых профилей, любые действия от имени пользователя в
клиенте Steam.

## 3. FunPay

* **Официального публичного API у FunPay нет** (проверено на 2026-10-05).
* Вся экосистема сторонних ботов работает через **неофициальный** доступ:
  сессионная cookie `golden_key` + CSRF-токен своего аккаунта
  ([примеры: FunPay-Tools](https://github.com/XaviersDev/FunPay-Tools-Android),
  [FunPayPHP](https://github.com/TimLiz/FunPayPHP), [Go-пакет funpay](https://pkg.go.dev/github.com/kostromin59/funpay),
  [FunPay Pulse](https://funpaypulse.com/docs)).
* Сайт защищён (в т.ч. антибот/Cloudflare); официальные правила автоматизации
  не опубликованы как разрешающие — использование неофициального доступа
  является **риском для аккаунта** (вплоть до блокировки), что подтверждают
  сами авторы сторонних библиотек («используйте на свой страх и риск»).

### Следствия для приложения

* Слой `FunPayAdapter` — интерфейс + **декларируемые capabilities**:
  `AVAILABLE` / `MANUAL` / `UNSUPPORTED`.
* Режим по умолчанию — **ручной** (`ManualFunPayAdapter`): оператор сам создаёт
  лоты на FunPay по подготовленным приложением текстам, сам вносит заказы и
  сообщения; приложение ведёт учёт, таймеры, шаблоны, статистику.
* Опциональный режим `GoldenKeyFunPayAdapter` (выключен по умолчанию,
  помечен как НЕОФИЦИАЛЬНЫЙ/РИСКОВАННЫЙ): только чтение данных своего
  аккаунта (заказы/сообщения), консервативный rate-limit, без обхода защит,
  отправка сообщений — только через ручное подтверждение. Пароль никогда не
  запрашивается; `golden_key` — только через Windows Credential Manager
  (keyring), в БД хранится лишь ссылка на credential.
* Любая отправка наружу — только в режиме подтверждённого действия и
  отключается полностью флагом `DRY RUN`.

## 4. Матрица автоматизации (итог)

| Действие | Механизм | Режим |
|---|---|---|
| Получить библиотеку своих аккаунтов | Официальный Steam Web API (ключ) | AUTO |
| Метаданные игр (цена/жанры) | публичный store endpoint, rate-limited | AUTO (кэш) |
| Проверка Steam Families для игры | эвристики + локальный датасет + ручная проверка | AUTO + MANUAL override |
| Добавление/удаление члена семьи | только вручную в клиенте Steam | MANUAL (учёт кулдаунов) |
| Объявления на FunPay | генерация текстов → публикация вручную | MANUAL |
| Заказы/сообщения FunPay | ввод оператором (по умолчанию) / чтение своего аккаунта (опция, неофициально) | MANUAL / ограниченный AUTO |
| Отправка сообщений клиентам | подготовленный текст → кнопка «Отправить» | по умолчанию Manual approval |
| Выдача/освобождение семейного доступа | учёт + инструкции оператору | полу-авто |

## 5. Twitch Drops — актуальные официальные возможности (проверено 2026-10)

| Интерфейс | Статус | Как используем |
|---|---|---|
| **Helix `GET /helix/streams`** | Официальный; публичные данные о live-стримах; достаточно app access token (client credentials) | Stream Selector: канал, зрители, язык, время старта. [1](https://dev.twitch.tv/docs/api/reference) |
| **Helix `GET /helix/games`, `GET /helix/search/categories`** | Официальный | Резолв названия игры → `game_id` для поиска стримов. [1](https://dev.twitch.tv/docs/api/reference) |
| **Helix `GET /helix/channels`** | Официальный | Информация о канале (широковещательный логин/заголовок). [1](https://dev.twitch.tv/docs/api/reference) |
| **Drops Entitlements (`/helix/entitlements/drops`)** | Только для **владельца игры/организации** с одобренным доступом (иначе 400 «client is not associated with a known organization») | НЕ используем — мы не издатель игры. [1](https://dev.twitch.tv/docs/api/reference) |
| **Список кампаний / прогресс просмотра / claim дропов зрителя** | Официальных публичных эндпоинтов **НЕТ**; кампании настраиваются вручную через Twitch Dev Console; прогресс доступен только во внутренней (непубличной) части веб-клиента | Кампании вносятся оператором (плюс публичные анонсы). Прогресс = локальная ОЦЕНКА + ручная верификация по инвентарю. Клейм — только руками пользователя. [4](https://discuss.dev.twitch.com/t/get-twitch-drop-campaign-by-api/40947) |

### Запрещено и НЕ реализуется (по ТЗ и по смыслу)

Фальсификация просмотра, искусственный watch-time, headless-фарм, обход
антибота/CAPTCHA/2FA, работа с внутренними GQL-эндпоинтами, кража/перенос
сессий, скрытая автоматизация. Прогресс Drops считается на стороне Twitch и
не может быть честно «симулирован» — любая симуляция является обманом
платформы и покупателей.

### Матрица автоматизации (Drops)

| Действие | Механизм | Режим |
|---|---|---|
| Поиск стримов игры | официальный Helix | AUTO |
| Открытие стрима/инвентаря/кампании | браузерный профиль ОС ПОЛЬЗОВАТЕЛЯ (уже авторизован) | полу-авто (кнопка) |
| Учёт кампаний, расписание, приоритеты | локально | AUTO |
| Прогресс дропов | оценка таймером + верификация по инвентарю | полу-авто |
| Клейм наград | пользователь в браузере | MANUAL (уведомление + кнопка) |
| Продажа аккаунта как stock | учёт/резервирование в БД | AUTO-учёт, выдача — вручную |
| Цены конкурентов на FunPay | ручной ввод (автоскрейпинг не обходит защиты) | MANUAL |

## 6. FunPay — внутренний веб-протокол (неофициальный, чистая реализация)

Изучен популярный бот автоматизации `sidor0912/FunPayCardinal` (496★,
активная разработка). **У репозитория нет лицензии** (`license: null`),
поэтому его код НЕ копировался и не вендорился; ниже — только наблюдаемые
факты протокола, по которым написан собственный клиент
`app/integrations/funpay/golden_key_client.py`.

Аутентификация и сессия (свой аккаунт, свой `golden_key`):
* GET `https://funpay.com/` c cookie `golden_key` (+ `cookie_prefs=1`) и
  user-agent браузера, где выполнен вход.
* Из `<body data-app-data="...">` читаются `userId`, `csrf-token`, `locale`;
  ник — `div.user-link-name`. `PHPSESSID` берётся из Set-Cookie и дальше
  передаётся вместе с ключом.
* Отсутствующий `user-link-name` = ключ недействителен (401/разлогин).

Заказы (страница «Мои продажи»):
* GET `https://funpay.com/orders/trade` (+ пагинация полем `continue` POST-ом).
* Строки — `a.tc-item`; классы: `info` = оплачен/ждёт выполнения, `warning` =
  возврат, иначе закрыт. Поля: `#`-номер (`div.tc-order`), описание лота
  (`div.order-desc div`), цена+валюта (`div.tc-price`), покупатель
  (`div.media-user-name span`, id из `data-href`), дата (`div.tc-date-time`),
  id чата = `users-<min>-<max>` из id продавца и покупателя.

Обновления и действия (канал `runner`):
* POST `https://funpay.com/runner/`, форма: `csrf_token`, `objects` (JSON),
  опционально `request` (JSON); заголовок `X-Requested-With`.
* Объекты-типы: `orders_counters`, `chat_bookmarks`, `chat_node`.
* Отправка сообщения: `request = {"action":"chat_message",
  "data":{"node": <chat_id>, "last_message":-1, "content": <текст>}}`.
* Лимиты: при «нельзя отправлять слишком часто» — ждать указанное время
  (клиент ждёт и повторяет, НЕ обходит).

Чаты (список и история):
* Список диалогов — объект `chat_bookmarks` канала `runner`: `data.html`
  содержит `a.contact-item` (`data-id` = id чата `users-<min>-<max>`,
  класс `unread` = непрочитанный, `div.media-user-name` = ник собеседника,
  `div.contact-item-message` = последнее сообщение).
* История: GET `https://funpay.com/chat/history?node=<chat_id>&last_message=-1`
  c XHR-заголовками → `{"chat": {"node": {...}, "messages": [{id, author, html}]}}`.
  `author` = 0 — системное (`div[role=alert]`); текст в `div.chat-msg-text`;
  автор = свой `userId` → исходящее (наши сообщения не считаем входящими).

Лоты (создание/изменение/закрытие — только свой аккаунт):
* Свои лоты подкатегории: GET `https://funpay.com/lots/<node>/trade`;
  строки — `a.tc-item`, id лота в `data-offer`, описание в
  `div.tc-desc-text`, цена в `div.tc-price[data-s]`; класс `warning` =
  лот деактивирован («закрыт»).
* Форма лота: GET `https://funpay.com/lots/offerEdit?offer=<id>` (свой лот)
  или `?node=<id подкатегории>` (новый лот); парсится `form.form-offer-editor`
  (input/textarea/select/checked-checkbox), поля вида `fields[summary][ru]`,
  `fields[desc][ru]`, `fields[payment_msg][ru]`, `price`, `active`,
  `node_id`, `csrf_token`.
* Сохранение: POST `https://funpay.com/lots/offerSave` (form-urlencoded,
  XHR-заголовки); `offer_id=0` = новый лот; ошибки в `{"errors": [...]}` /
  `{"error": ...}`. Закрытие = сохранение с пустым `active` (деактивация,
  лот остаётся в аккаунте); удаление = поле `deleted=1` — НЕ используется
  приложением намеренно.
* Поднять лоты (не используется): POST `https://funpay.com/lots/raise`.

Что сознательно не автоматизируется: обход антибота/капчи, удаление лотов,
любые действия без явного согласия оператора.
Риски внутреннего протокола и возможных ограничений аккаунта — на операторе.
